# UX polish notes for 1.0

## Principles
- Never turn missing data into a positive/easy score.
- Keep route setup separate from the delivery clock.
- Prefer one-tap/one-field checkpoint actions during a workday.
- Explain why an account is required only where it is actually required.
- Preserve local functionality when cloud/payment/AI services are unavailable.
- Clearly distinguish estimates from factual route data.
- Never imply original evidence images are cloud-backed when they are not.

## Copy decisions
- Use “AI screenshot analysis” rather than implying access to employer systems.
- Use “estimated finish time” rather than “finish time.”
- Use “documented delay” for user-entered delay duration.
- Use “Compare Free and Pro” before purchase rather than aggressive upgrade wording.
- Explain that Free AI requires sign-in because usage is account-based.

## Empty/error states
- No routes: explain how to create the first route.
- Not enough forecast data: say how many useful checkpoints are needed.
- No analytics: complete routes first.
- Offline cloud/AI: preserve local work and offer retry, not destructive reset.
- No store products: state subscriptions are unavailable from the current store account/build.
